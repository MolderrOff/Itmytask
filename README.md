# IT-MyTask: Система управления заявками в IT-аутсорсинге

Проект представляет собой демонстрацию навыков **Back-end разработки** на стеке .NET. Фокус сделан на проектировании архитектуры веб-приложения, взаимодействии с реляционными СУБД и развертывании в Linux-среде.

**Демонстрация (Live Demo):** [http://37.143.10.243](http://37.143.10.243)  
*(Развернуто на сервере под управлением Ubuntu 22.04 LTS)*

---

## 🛠 Стек технологий и окружение

* **Платформа и фреймворк:** .NET 8 SDK, ASP.NET Core (Razor Pages / MVC)
* **Язык программирования:** C#
* **База данных и ORM:** MySQL, Entity Framework Core (подход Code First)
* **Среда развертывания:** Linux (Ubuntu VPS)
* **Инструменты администрирования:** Midnight Commander (mc), Git LFS, cURL, build-essential

---

## 🔥 Ключевой функционал и особенности реализации

* **Бизнес-логика**: Моделирование процессов учета, распределения и выполнения заявок (замена оборудования, настройка периферии) между сотрудниками и клиентами внутри IT-компании.
* **Интерфейс**: Реализован полноценный цикл CRUD (создание, просмотр, изменение, удаление объектов) для управления заявками.
* **Автоматическая инициализация БД**: При первом запуске приложение проверяет наличие базы данных и самостоятельно генерирует её структуру на основе моделей данных (EF Core Миграции).
* **Система наполнения (Data Seeding)**: Реализован специализированный эндпоинт `/Work/GetWorks` для быстрой генерации и демонстрации тестовых данных на пустых окружениях.

## 🚀 Развертывание и деплой на Linux (Production)

Приложение развернуто на выделенном Linux-сервере. Архитектура деплоя спроектирована с учетом базовых практик безопасности и изоляции сервисов.

### Выполненные шаги по настройке сервера:

1. **Изоляция и безопасность:** 
   * Обновлены пакетные менеджеры (`apt update && apt upgrade`).
   * Настроены разграничения прав доступа: запуск приложения изолирован от `root`-пользователя. Созданы отдельные системные пользователи с ограниченными привилегиями под каждый работающий сервис.
   * Настроена конфигурация брандмауэра для контроля входящего/исходящего трафика.

2. **Окружение и зависимости:**
   * На сервере развернута среда сборки компилируемых языков (`build-essential`, `gcc`) для поддержки нативных библиотек.
   * Установлен `Git` с расширением `Git LFS` для корректной обработки тяжелых бинарных ассетов.
   * Настроена глобальная конфигурация контроля версий и кэширование учетных данных (`credential.helper store`).
   * Установлен актуальный рантайм и пакет разработки **.NET 8 SDK**.

3. **Сборка и жизненный цикл приложения:**
   * Выполнено клонирование кодовой базы из репозитория.
   * Запущено восстановление внешних NuGet-пакетов, исключенных из системы контроля версий (`dotnet restore`).
   * Произведена компиляция и валидация проекта (`dotnet build`).

4. **Сборка релизной версии (Production Release):**
   * Вместо нестабильной команды `dotnet run` для продакшена собирается оптимизированный билд:
     ```bash
     dotnet publish -c Release -o /var/www/itmytask
     ```

5. **Настройка фоновой службы (Systemd daemon):**
   * Для обеспечения работы приложения в режиме **24/7** и автоматического перезапуска при сбоях или перезагрузке сервера, настроена системная служба Linux.
   * Создан конфигурационный файл демона `/etc/systemd/system/itmytask.service`:
     ```ini
     [Unit]
     Description=IT-MyTask ASP.NET Core Application
     After=network.target

     [Service]
     WorkingDirectory=/var/www/itmytask
     ExecStart=/usr/bin/dotnet /var/www/itmytask/YourProjectName.dll --urls=http://*:80
     Restart=always
     RestartSec=10
     User=limited_user_name
     Environment=ASPNETCORE_ENVIRONMENT=Production

     [Install]
     WantedBy=multi-user.target
     ```
   * Управление жизненным циклом службы осуществляется стандартными системными командами:
     ```bash
     sudo systemctl daemon-reload
     sudo systemctl enable itmytask.service  # Добавление в автозагрузку ОС
     sudo systemctl start itmytask.service   # Старт фонового процесса
     sudo systemctl status itmytask.service  # Мониторинг статуса службы
     ```

   **Сетевая конфигурация:**
   * Серверная часть приложения привязана к порту `80` и слушает входящие запросы со всех сетевых интерфейсов (`--urls=http://*:80`).

## 🏗 Инструкция по локальному запуску (для разработчиков)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Убедитесь в наличии установленного .NET 8 SDK и СУБД MySQL.
3. Настройте строку подключения к вашей локальной MySQL в файле конфигурации (`appsettings.json`).
4. Выполните команды восстановления зависимостей, сборки и запуска:
   ```bash
   dotnet restore
   dotnet build
   dotnet run
   ```
5. Для первичного наполнения базы данных тестовыми заявками перейдите по адресу: `http://localhost:5000/Work/GetWorks`.
